See what's being played before you start, and know why a join didn't work. Your friends' lines now name the mode and the map ("SvM Classic · Virus Vault"), and every server shows its open matches by mode, map and players, in the launcher and in the overlay. The server no longer ends a public match when its host leaves, searches skip lobbies that are already full, and when a join fails or a search finds nothing, the launcher tells you why: a full lobby, a closed one, or game data (mods) that differ from yours.

## Play

Already on 0.4.3? The launcher updates itself. New here? Download **`launcher.exe`** (Windows) or **`launcher-linux-x86_64`** (Linux, Steam Deck) below, run it, press **Connect**, then **Play**. More in [Play in five minutes](https://github.com/JDevWebb/5th-echelon-enhanced#play-in-five-minutes).

## What's new

### Playing
- **See what's being played** (thanks to ijsman's suggestion). A friend in a match now reads "SvM Classic · Virus Vault · in a match with Tank" (the exact mode: SvM Blacklist or Classic, Team Deathmatch, Uplink Control, Extraction, or the co-op mission), in the launcher and in the overlay; a friend in a lobby reads "In a lobby with Tank". And every server says what's being played on it: its public matches by mode, map and players (6/8), how many private matches there are, and how many players wait in lobbies. Never anyone's name, and no more than a search in the game shows. It's under **Playing now** on the Play screen's Friends card, on each server in the server list (and when you point at one in the server menu), and in the overlay's Friends pane. It needs your server on 0.4.4.
- **The server no longer ends a public match when its host leaves.** Players who joined it from a search were left out of who was in the match, so when its host left, the server ended it for them and refused their games' attempts to carry on. They now count as in the match, so their games may carry it on.
- **Searches skip lobbies that are already full** (thanks to FANTOMAS's, d15_HB's and Oni's reports). A co-op lobby starts with two seats, and the host can raise it to four or six; the search went by the most a lobby can hold, so it offered lobbies full at their size, and joining them failed. It now goes by the seats the host has set, so a host raising the size opens the lobby to searches again. An invitation no longer puts you into a lobby that's full, either.
- **Nobody can hide lobbies by joining them.** Now that players who joined count towards a lobby being full, one player could have filled lobbies without playing in them. A player is now in one match and one party at a time, and gets into a public lobby only while it has a seat (or with an invitation).
- **A search that finds nothing because of mods says so** (thanks to ijsman's report). The game only shows lobbies whose game data is the same as yours, and says nothing of the others, so a game with a mod never sees an unmodified game's lobbies, and the other way round. When a search finds nothing while such lobbies are open, the launcher asks how it went and explains: remove the mod, or verify the game's files in Steam or Ubisoft Connect.
- **A failed join says why** (thanks to PlaySkill's report). The launcher now tells a full lobby from a locked or closed one, and when two games' data differ it says whose: "Theusma01's game is unmodified; yours has the balaclava mod".
- **The game tidying its own party isn't a failed join** (thanks to Renegade's and nano_machine's reports). When your party closes as you go into a match, the game reports a failed join to it; that's no longer counted against you, doesn't ask for your game's log, and doesn't ask you how it went.
- **Joining a public match through the relay connects at once.** The match's players reach someone joining it from a search a few seconds before the join reaches the server; since 0.4.3 the relay waited for the join. It now carries them for those seconds (only them, and only through the relay, so nobody's address is handed out).
- **"Too many failed logins" only after wrong passwords** (thanks to Ghost_Leader's report). Every sign-in counted towards the limit, even those that worked. Now only a wrong password or key counts, and the separate limit on how many sign-ins an address makes in a short time says "Too many sign-ins from your address in a short time".

### The launcher
- **Reports say how the game ended.** A report now carries the game's exit code (a crash's, say), and the game writes a last line to its log when it closes normally, so a crash, the game being killed and a quit can be told apart.
- **The server list says what's being played** on each server (above).
- **A Uplay emulator is noted, not refused.** When the game's Ubisoft Connect DLL has been replaced by an emulator, the launcher says so once on the Play screen: how you run your game is up to you, but it isn't a setup we support, so we may not be able to help if something doesn't work with it. Close the notice and it doesn't come back. The game's log notes it too.

### Running servers
- **Updates go out in update windows, booked ahead.** A maintenance window is now for an update or for other maintenance, and the rollout installs a release on a server only during an update window booked for it or for the whole network, so players know days ahead when their server restarts: launchers say "Server update today, 8:00 pm" and that it's down for about two minutes, and the game warns them 10 minutes before. Within its window a server updates at once, players on or not. Until a window is under way, the rollout waits, and the Updates page says when the next one is. **Update now, without a window** sends an urgent fix out as before (each server when it's quiet, or within two hours), and rolling back always goes out at once. A whole network's update window covers every server and the coordinator. Book update windows after updating the coordinator, or 0.4.5 won't go out ([operations](https://github.com/JDevWebb/5th-echelon-enhanced/blob/main/docs/operations.md#maintenance-windows)).
- **"Update from the project's roadmap"** on the admin UI's Roadmap page, at any time, not only on an empty roadmap: it shows what's added, moved, changed and removed, then brings Shipping, Next and Later up to the project's for the release. Requested, and items made of players' suggestions, stay as they are with their links.
- **Sessions tells a match's end from a dropout.** Traffic falls to almost nothing on the results screen, and few matches write stats, so a match ending around a player read as them dropping out. The host closing a match now ends their stay in it (it showed them in it until their game timed out), a guest who left isn't also "removed by the host", and one dropout is one problem, not one for each way its traffic fell.
- **Sessions says what a failed join ran into:** a full lobby, a locked session, a room just closed, or whose game data differs (and from what). The game's own party tidying isn't shown as a problem.
- **A connection stalling isn't a dropout:** a fall in relayed traffic while the player's own game and launcher went quiet too is their connection, and Sessions says so.
- **A sign-in whose replies never reach the player** (their game keeps sending but never acknowledges the server) is noted, once per player in 10 minutes, and shown as one problem per player. Ghost_Leader's replies were lost on the way for two hours.
- **Searches hidden by game data** are a problem on Sessions too, once per player, naming both sides' data.
- **Refused relay pairs are logged** once a minute, with both names and why.
- **What's being played:** the server answers `GET /api/playing` (on with `info`, worked out at most every 5 seconds) and sends it with its heartbeat; the coordinator bounds it and lists it with the server in the directory ([server settings](https://github.com/JDevWebb/5th-echelon-enhanced/blob/main/docs/server-settings.md)). `/api/presence` and the friends API now include each match's game mode.
- **The coordinator's check of each server's API survives a slow DNS lookup.** It falls back on the address the name last had, and a lookup that fails is alerted as the coordinator's own DNS, not as the server's web server being down (on 2026-10-08 a slow resolver made every server "fail" at random).
- **A host's room limit** counts every live room it made, a match it left that guests play on included.
- **Players' addresses in public matches and parties stay theirs.** Anyone can be counted in a public match or a party without playing in it, and a probe between two players (NAT traversal) gives each the other's address, so a stranger could have collected the addresses of everyone in any public match. In a public match or a party (anyone can join a party by its number), a probe now goes ahead only with its host, or when both players' games ask to reach each other, as two players really in it do; anyone else reaches the players through the relay, which shows no one's address. Private matches are as before.
- **Hardening:** a failed join's answer names the other side's game data only for the room the server just gave that player, never for any room the game names (it would have told who hosts a private match, and with what mods).
- **The coordinator's hourly backup of its join token and reports works again.** From 0.4.3 its sandbox stopped GNU tar's incremental copy ("Cannot stat: Function not implemented"), so every hourly copy failed; the live backup of its database was unaffected. Run the installer again after updating to fix the unit.
- **`scripts/sign-release.sh` finds the server image** however buildx spaces its JSON. 0.4.3 was signed without its image (from 0.4.4 on, each release's signature covers it).

Servers and the coordinator both need 0.4.4 for the Sessions changes; the server list shows what's being played once both are.
