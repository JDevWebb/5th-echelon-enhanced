Fixes from the first days of 0.4.4: names with slurs or hate refused, no more duplicate matches in the server's lists after a host leaves, game logs that keep what went wrong, Steam Input for Steam copies, and the overlay keeping out of the game's window handling. Plus three new game options to choose from, from MPW1412: the mouse moving 1:1, a brighter picture and no automatic climbing. Chat moves to 0.4.6.

> [!TIP]
> **Thank you to everyone who sent a report from the launcher or wrote to Support.** This release came from them:
> - **Alessenchaleur**: the launcher's list showing several matches after one was started again.
> - **Tea_bag** and **PsykoGun**: logs that turned out to hold nothing but the overlay's errors, which is why hangs and crashes couldn't be traced.
> - **RAZA**: controllers, which Steam Input only handles in games Steam starts.
>
> Send yours from **Settings › Feedback › Send feedback**.

## Play

Already on 0.4.4? The launcher updates itself. New here? Download **`launcher.exe`** (Windows) or **`launcher-linux-x86_64`** (Linux, Steam Deck) below, run it, press **Connect**, then **Play**. More in [Play in five minutes](https://github.com/JDevWebb/5th-echelon-enhanced#play-in-five-minutes).

## What's new

### New game options (thanks to MPW1412)
The first time 0.4.5 starts, the launcher lists these with what we recommend already chosen, and the game starts once you've saved your choice; a new install chooses them in its setup. **Settings › Game** changes them any time.
- **Mouse moves 1:1** (recommended). The game caps how far the view turns in a single frame, so a fast flick turned less than a slow one: its negative mouse acceleration. The cap is now widened far past any real movement, so aiming is linear, but a bad input spike is still caught and can't flip the camera (which removing the cap outright does under Proton). If you use ThirteenAG's Fusion Fix with its own `DisableNegativeMouseAcceleration` on, that one stays in charge and this option is greyed out; set it to 0 in `SplinterCellBlacklist.FusionFix.ini` to use this one.
- **Brighten the picture** (off unless you choose it). The game caps its brightness low, which looks dark, under Proton especially. This lifts the cap and sets a brighter picture, from a slider, by editing `Blacklist.ini` while the game is closed; turning it off puts the original values back.
- **No automatic climbing** (off unless you choose it). Sam stops climbing and vaulting over edges by himself when you sprint into them (Active Sprint): climbing is only ever manual. It takes effect the next time the game starts.

### Playing
- **No more ghost matches in the lists** (thanks to Alessenchaleur's report). When a match's host left, the players carrying on moved into a copy of it, but the server kept them in the old one too, so it stayed listed under the host who had left until that host signed out (once for over four hours), beside the match really being played. Players who carry on now leave the old match, and it ends when the last of them has. It needs your server on 0.4.5.
- **Names with slurs or hate aren't allowed.** A new name, or a rename, that's a slur, hate, or a web address is refused, with a word list that sees through look-alike letters and spacing (swearing is fine). Players whose name from before breaks the rules are asked to choose another: the launcher says so on the Play screen with a Rename button, the game isn't let in until they do, and friends and invitations carry on under the new name. The network's admins can ask any player to rename from the admin UI (**Ask to rename**, on the player's page).
- **Players who join a match are counted in it.** Since 0.4.4 the server counted a player joining from a search only while the match had a seat by its own count, which misses players who came in with a party; the host's game had let them in all the same. One in eight such players wasn't counted, so the match looked emptier than it was and searches offered it when it was full (one player was offered a full match ten times). A join now counts whenever the game makes it.
- **Steam Input for Steam copies on Windows** (thanks to RAZA's report). Steam applies Steam Input (controller layouts, Xbox 360 pads and the rest) only to games it starts, and the launcher started the game itself. For a Steam copy, Settings now has **Start the game through Steam**: Play then asks Steam to start it. Steam then picks DirectX 9 or 11 (its Play menu or launch options), and the launcher can't tell from the game's exit code whether it crashed. Off by default.
- **The overlay keeps out of the game's window handling.** With the panel open, every window message was handled a second time, late and from the overlay's own thread: Alt could open the window's menu, Alt+Space its system menu, and minimising or moving happened twice. Alt+F4 still quits with the panel open.

### Reports
- **The game's log keeps what went wrong** (thanks to Tea_bag's and PsykoGun's reports). While the game's window had no size (minimised), the overlay wrote two errors on every frame: one log reached 92 MB, and since a report sends the end of the log, reports held only those errors. A line repeated within a minute is now left out, with a note of how many were.
- **No false errors in the game's log.** A game whose network adapter has more than one address (as Wine lists them) was told its adapter wasn't found, on every call (179 times in one log); every address now counts, and if none matches it's said once. A copy without its own addresses file (Ubisoft Connect's, in Program Files) no longer logs that as an error: the built-in addresses are used, as before.
- **The previous game's log is the one that matters.** Steam and Ubisoft Connect start the game, close it at once and start it again, and that half-second run took the place of the previous run's log, so a report never had the game that crashed. A run that short is now added to the next one instead.

### Running servers
- **The coordinator's own machine updates last.** A rollout never tries a release first on the server that shares the coordinator's machine (that machine's updater installs the coordinator too, which then carried on the rollout under the new release's rules: in 0.4.4's rollout, the coordinator took itself as the first server, and after the update waited for an update window and tried a second server first). That server, and with it the coordinator, now updates once every other server runs the release. The coordinator works out which server it is from the servers' addresses, or from `--local-server`. A server that never updates holds it back for two hours at most, so the coordinator isn't kept off a release.
- **Hardening:** no server is taken as the one a release was tried on first for saying it already runs it (servers report their own version, so one could have skipped that step for everyone).
- **Which client builds your servers take** (admin UI › Security › Client builds). The launcher and the game add-on now send a fingerprint of their own file (its SHA-256) when they sign in, and the coordinator knows the fingerprints of the project's signed releases from their `SHA256SUMS`. A modified or development build, or a client older than 0.4.5, is noted on Sessions (*Not one of the project's releases*); switch to **Enforce** and it's refused, except for identities you allow (developers: **Allow other builds** on their player page). It starts in **Report**: check Sessions before enforcing, and enforce only once servers refuse clients older than 0.4.5. A client can be made to send a release's fingerprint, so this stops honest modified builds and casual tampering, not a determined attacker.
- **Relay drops that last.** A player's relayed traffic falling now counts as a drop once it's still down ten seconds later. Co-op's traffic dips for a few seconds as it plays, and in 0.4.4's first 40 hours most of eu1's 268 relay drops were co-op players who carried on.
- **An old game left running is answered more slowly.** An outdated client is refused at once, as before; the same sign-in again within a minute now waits 10 seconds for the same answer. One 0.4.2 game left running was refused 48,269 times in 40 hours.
- **Sessions says when a player moved on** to a new match or party, rather than leaving it.
- **Answers that don't get lost.** The server's web port (the game's online config and the community API) answers a request after its first line, and closed the connection without reading the rest. A client still sending its headers then had the connection reset, and lost the answer it was reading (`Connection reset by peer`). The rest is now read and dropped first, as it already was for a refused upload. It showed up as a test that failed in half the runs.
- **CI and releases run on Node.js 24** (GitHub retires Node.js 20 actions), with a pinned protoc for the Windows builds.

## Updating to 0.4.5

**Servers of your own:** update as usual (the rollout, in an update window, or the installer by hand).

**Rolling 0.4.5 out:** the rollout is run by the coordinator that's there, 0.4.4's, which can still pick the coordinator's own machine to try the release on first. Steer it with update windows: book windows for the other servers first (on the community network, na1 and oceania), and a window for the whole network afterwards, for the coordinator's machine (eu1) and the coordinator. From 0.4.5 on, the coordinator's machine goes last by itself.
