# 0.5.5 "Open Door"

**0.5.5 is about getting into matches.** You can join a match whose round is under way, players whose route to the matchmaking server fails sign in through the relay near them, joins that kept failing between some players now go through the relay, and the match queue waits for a seat, not for the round to end. The launcher updates by itself.

## Getting into matches

- **Join a match under way.** Quick match, the launcher's **Join**, **Join now** and the Matches tab now take you into a match whose round has started: you join mid-round, on a team, as the game itself already allowed by invitation. Only a host whose game is turning players away keeps them out for a while. The Matches tab shows such a match as *Under way: you join mid-round*.
- **The match queue waits for a seat.** A full match offers **Join when a seat opens**; you're in line, the game starts if it isn't running, and you join by yourself, mid-round, when a seat is yours. (In 0.5.4 a match under way offered *Join when this round ends*, and some players found it never let them in.)
- **Joins that kept failing go through the relay.**
  - A player who fails twice to join one host that others got into goes through the relay, and so does a host three players failed to join in half an hour more often than anyone got in.
  - A player moved to the relay stays there for a week on that network, instead of starting direct and failing again every session.
  - A router that forwards a different port from the one the game's packets leave from is checked where the game sends from, and relayed when that doesn't let others in.
  - The game now tells the server which player it couldn't reach when a join fails (not always the host: every player in a match connects to every other), and that player goes through the relay.
- **Signing in through the relay near you.** Since 0.5.0 every player signs in to one matchmaking server, and some players' routes to it lose the replies. Now:
  - when the game's calls keep losing their answers, it notices, and from the next start that network signs in through the nearest relay for a week;
  - when the server doesn't answer the launcher at all but the relay near you does, the launcher and the game go through the relay straight away;
  - or choose it yourself: **Settings › Network › Always sign in through the relay near you**.

  The sign-in, the game's online services and its online config all go through the relay, which passes them on.
- **Your ping over HTTPS.** Players whose network blocks the game's traffic (0.5.2's HTTPS tunnel) now have a ping to the relay, in the overlay and for the server's choice of matches.

## Fixed

- **Green and purple screens under Proton.** On Linux (Steam/Proton), the title screen and the SMI table could show green textures with purple stripes. A crash fix added in 0.5.2 for a Windows graphics driver misread how Proton's graphics layer hands out textures and cut the videos' frames short. It's now off under Wine and Proton, where that crash doesn't happen.
- **A closed maintenance window blocks Play at once.** During a window that only testers may play in, other players could still start the game for up to 10 minutes and were refused in game. The launcher now checks again as the window starts.
- **Port forwarding on routers that use PCP.** The request the game sends to open its port on such a router carried a value that should be random and wasn't. It's random now.
- **Crashes are recorded under the release that crashed.** A crash is sent at the next start, which may be a newer release's. It now carries the release it happened in.

## For server admins

- **Joining mid-round:** searches now answer matches under way. Nothing to set.
- **Relays pass sign-in on.** A relay's Caddy passes the API, the game's online config, content and uploads on to the matchmaking server, and its tunnel passes the sign-in and secure service on. Relays say `relay-sign-in` in their `/api/info`. Run the installer again on each relay (as `--mm-record` was given before) to get the new Caddy routes.
- **The Sessions page** has queue events (a player's wait for a full match: place taken, left, let in), moves to the relay that last a week, and the players a game couldn't reach (`unreachable`).
- **`scripts/join-stats.sh`** shows how joins into matches went on a server, by whether joiner and host were relayed, read-only.
- **The bot tests** have `match-queue` and an updated `match-state` (a match under way is offered).

## Updating to 0.5.5

**Players:** the launcher updates by itself. **Servers of your own:** update as usual. For signing in through relays, run the installer again on each relay. As with every release, a server on 0.5.5 takes 0.5.5 games and launchers only.
